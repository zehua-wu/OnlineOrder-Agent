# OnlineOrder Agent

FastAPI service that turns natural-language ordering requests into a bounded set
of calls to the existing Spring Boot backend. Spring remains the source of truth
for catalog, cart, inventory, checkout, authentication, and authorization.

The first implemented tool is `search_menu`, backed by the existing
`POST /api/search` endpoint.

## Architecture

```text
React -> POST /agent/chat -> FastAPI orchestrator -> OpenAI Responses API
                                  |                       |
                                  +-- session store       +-- search_menu call
                                  |   (memory or Redis)            |
                                  +-- tool executor -> Spring Boot-+
```

The tool loop has a hard step limit and rejects repeated calls with identical
arguments. The request's `Authorization` header stays in request context and is
forwarded to Spring; it is never included in model input or session storage.

FastAPI, rather than the model, owns the working state for each conversation:

```text
messages                    what the user and assistant said
state.search                the effective, merged search filters
state.last_search_results   positions mapped to real Spring menuItemId values
state.selected_item         the result explicitly selected by the user
```

For example, after a search for mild chicken under $15, a follow-up saying
"also with avocado" sends only the new keyword from the model. The tool executor
merges it with the stored chicken, spice, and price constraints before calling
Spring. A successful search replaces `last_search_results`; a failed tool call
does not modify working state.

When the user says something like "the second one looks good", the internal
`select_search_result` tool resolves position 2 against `last_search_results` and
stores its real ID in `selected_item`. This is conversation state only and does
not modify a cart.

## Local setup

Python 3.11+ is required.

```powershell
conda activate onlineorder-agent
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
uvicorn app.main:app --reload --port 8000
```

If you are not using Conda, create and activate a normal `.venv` first.

Set `OPENAI_API_KEY` in `.env`. By default, the agent calls the Spring service at
`http://localhost:8080` and keeps sessions in process memory. To use Redis, set
`SESSION_BACKEND=redis` and `REDIS_URL`.

## API

Health check:

```http
GET /health
```

Chat:

```http
POST /agent/chat
Authorization: Bearer <customer-jwt>   # required; CUSTOMER accounts only
Content-Type: application/json

{
  "message": "帮我找 15 美元以内、不太辣、有 avocado 的鸡肉",
  "sessionId": null
}
```

The response keeps conversational text short and returns deterministic card data
copied from the Spring search result rather than generated by the model:

```json
{
  "sessionId": "...",
  "answer": "I found several mild chicken options under $15.",
  "toolSteps": 1,
  "cards": [
    {
      "position": 1,
      "menuItemId": "...",
      "name": "Chicken Tortilla Soup",
      "restaurantName": "Casa Sol",
      "price": 7.99,
      "imageUrl": "...",
      "availableQuantity": 12,
      "spicyLevel": 1,
      "servingTemperature": "HOT"
    }
  ],
  "totalResults": 10,
  "hasMore": true
}
```

The initial response contains at most three cards. Load later cards from the saved
session without calling search or the model again:

```http
GET /agent/sessions/<sessionId>/cards?offset=3&limit=3
Authorization: Bearer <customer-jwt>
```

Reuse the returned `sessionId` for subsequent turns. Session records are stored
as one atomic document containing both `messages` and `state`. With Redis, the
key namespace is `agent:session:<sessionId>` and the configured TTL applies to
the whole conversation.

## Tests

```powershell
pytest
```

No OpenAI key, Redis, or running Spring service is required for the test suite.

### Windows Git Bash and Redis Unicode output

Session messages are stored as normal Unicode strings. On Windows, piping
`redis-cli` output through a Python process with a legacy console encoding can
display UTF-8 bytes as mojibake even though Redis contains valid text. Inspect a
session using the Conda interpreter with UTF-8 output enabled:

```bash
docker exec onlineorder-redis redis-cli --raw GET "agent:session:$SESSION_ID" |
  PYTHONIOENCODING=utf-8 /c/Users/zhwu2/miniconda3/envs/onlineorder-agent/python.exe -m json.tool
```

## Current boundary

This version intentionally exposes only `search_menu`. It supports search
refinement and remembers result positions/IDs, so the next capability can safely
resolve "the second one" before adding a cart tool. Cart and checkout should be
added through the same executor/client layers. Checkout must not be made an
ordinary auto-executed tool: add a persisted pending action and an explicit
confirmation phase before enabling it.
